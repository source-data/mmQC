## [2026-09-15] decision | The SkillSet digest covers **content**, not just version labels: sorted `{name, version, content_hash}` over canonical JSON. A version number is a claim about content; the hash is the content. Both are carried so a digest mismatch can be *explained* ("`shared` moved v1→v2") rather than merely reported. `session_cache_key` took the digest as an **optional** argument rather than a required one — with none supplied it derives a SkillSet from the assembled runtime, so the pre-existing property that editing a `SKILL.md` *inside a runtime* changes the key survives unweakened.

## [2026-09-15] decision | `dag.yaml`/`README.md` render edges from the **prose** (`invoked_skills`), not from `requires`. Validation already asserts the two agree, so both give the same answer — but the prose is what runs, and a generated picture should be drawn from the thing that runs. Made a test (`test_the_dag_edges_match_the_prose`) so gate 6B does not decay into a one-time human read. Generation is deliberately a pure function of skills+manifest: no timestamps, no absolute paths, no filesystem ordering. Writing twice a second apart cannot catch a timestamp, so there is a **separate** test asserting the rendered text contains neither the checklist path nor the current year — a drift check that reports noise on someone else's machine teaches people to ignore it, which is the only way it can fail completely.

## [2026-09-15] finding | An independent code review of the Milestone 6 work found **three real defects that a green 296-test suite did not catch**, all in the same seam: once more than one version of a skill can exist, every place that resolved "the" version by convention becomes a latent bug. (3) *Medium* — the per-SkillSet output directory was keyed on `len(skill_sets) == 1`, i.e. cardinality rather than intent; `--unpin X --versions v2` expands to exactly one set, so a variant's predictions were written straight over the baseline's.
